## 01 HTTP 请求 & 响应
1. # 一个标准的 HTTP 请求和响应，都有哪些部分？
HTTP 请求
请求行：请求方法（GET/POST）、URL、HTTP 版本
请求头（Headers）：携带附加信息，如客户端类型、token、内容类型
请求体（Body）：POST 等方法携带的数据，GET 一般没有请求体
HTTP 响应
状态行：HTTP 版本、状态码、状态描述
响应头（Headers）：服务器信息、返回数据类型等
响应体（Body）：服务器返回给客户端的真实数据（网页文本、笔记 JSON 等）
2. # 提交一篇长笔记，选 GET 还是 POST？为什么？
选用 POST。
原因：
GET 的数据放在 URL 里面，URL 长度有限，不适合传输长文本笔记；
GET 数据会直接暴露在地址栏，不安全；
POST 将笔记内容放在请求体中，没有长度限制，适合提交较长的笔记内容。
GET 一般只用于查询、读取数据，不用于提交新增数据。
3. # HTTP 状态码是什么？常见状态码 + JotangNote 场景
HTTP 状态码：服务器返回给客户端的数字编码，用来告诉客户端本次请求成功 / 失败的类型。
常见状态码：
200 OK：请求成功。查询笔记成功时返回。
201 Created：创建成功。新建笔记保存成功返回。
400 Bad Request：请求参数错误，提交笔记格式不对。
401 Unauthorized：未登录，没有 token，无法读写笔记。
403 Forbidden：登录了，但没有权限访问这篇笔记。
404 Not Found：笔记不存在，访问了不存在的笔记 ID。
500 Internal Server Error：服务器内部代码出错。

## 02 接口 / API
 # 设计「获取某篇笔记详细内容」接口需要考虑什么？
请求行/请求方式：使用GET，这是读取查询数据，不修改服务端资源。
路由 URL：例如 /api/note/{note_id}，用 note_id 标识要查询的笔记。
权限校验：检查用户是否登录、是否有权查看这篇笔记（是否是本人笔记），无权限返回 401/403。
入参：笔记 ID（路径参数）；校验 ID 是否合法。
返回数据结构：返回笔记 id、标题、正文、创建时间、修改时间等字段；如果笔记不存在返回 404。
异常处理：ID 不存在、参数非法、数据库查询失败等情况，返回对应 HTTP 状态码 + 错误提示。

## 03 JSON
1. # JSON 格式的数据长什么样？
JSON 是纯文本格式，用键值对组织，支持对象{}、数组[]，基础类型：字符串、数字、布尔、null。
规则要点：
键名必须用双引号；
字符串必须双引号；
不能写注释；
支持嵌套对象和数组
2. # 如何使用你所选择的编程语言来将对象转化成 JSON, 或者将 JSON 转化成一个对象?
（1）Python 对象 → JSON 字符串：json.dumps()
python中运行
import json
note = {"note_id":1, "title":"test"}
json_str = json.dumps(note, ensure_ascii=False)
（2）JSON 字符串 → Python 对象：json.loads()
python中运行
data = json.loads(json_str)
（3）如果是 FastAPI，框架会自动完成 Python 模型和 JSON 的序列化 / 反序列化，不用手动调用 json 库。

## 04 HTTPS
# HTTPS 的加密过程是怎么样的？
HTTPS = HTTP + TLS/SSL，在 HTTP 通信之前，会先完成 TLS 握手，建立加密通道：
客户端发起请求：客户端向服务器发送支持的加密套件、TLS 版本。
服务器返回证书：服务器返回 CA 颁发的数字证书（包含服务器公钥）。客户端校验证书合法性，确认服务器身份，防止冒充。
客户端生成随机密钥：客户端生成一个对称加密密钥，用服务器的公钥加密，发给服务端。
服务器解密得到密钥：服务器用自己的私钥解密，拿到这个对称密钥。
双方使用对称加密传输 HTTP 数据：握手完成，后续 HTTP 请求 / 响应全部用这个对称密钥加密传输。
补：原理区分：
非对称加密（公钥私钥）：只用来安全协商出对称密钥，不加密业务数据
对称加密：加密真正的 HTTP 报文（账号、密码、笔记内容），速度快
    SSL 是早期加密协议，存在严重安全漏洞，现已废弃；TLS 是 SSL 的升级版，修复了 SSL 的安全缺陷，是现在 HTTPS 真正使用的协议。口语中 “SSL 证书” 只是沿用旧称呼，通信实际使用 TLS。
